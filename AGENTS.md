## Project Overview

## Technology Stack

### Core Dependencies

- **loguru** (~0.7.3) - Modern Python logging with structured logging support

### Development Tools

- **ruff** - Fast Python linter and code formatter (configured in `pyproject.toml`)
  - Line length: 88 characters
  - Target Python version: 3.11
  - Enabled rules: pycodestyle (E, W), pyflakes (F), isort (I), flake8-bugbear (B), flake8-comprehensions (C4), pyupgrade (UP)
  - Quote style: double
  - Indent style: space

### Markdown Linting

- **markdownlint-cli2** - Fast Markdown linter
  - Enforces: MD022 (blanks around headings), MD031 (blanks around fences), MD032 (blanks around lists)
  - Config: `.markdownlint-cli2.yaml`
  - Runs automatically via pre-commit hook on commit
  - Manual run: `uv run pre-commit run markdownlint --all-files`

## Build and Development Commands

### Environment Setup

```bash
# Create virtual environment
uv venv

# Activate environment
source .venv/bin/activate  # Linux/macOS
.venv\Scripts\activate     # Windows

# Install dependencies
uv pip install -e .
```

### Running the Application

```bash
# Run the main application
uv run python app.py

# Run test/example files
uv run python test/example_logging.py
```

### Linting and Formatting

```bash
# Format code with ruff
ruff format .

# Check linting
ruff check .

# Fix auto-fixable lint issues
ruff check --fix .
```

### Pre-commit Hooks

```bash
# Install pre-commit hooks (run once after cloning)
uv run pre-commit install

# Run all hooks manually on all files
uv run pre-commit run --all-files

# Run specific hook
uv run pre-commit run markdownlint-cli2 --all-files
uv run pre-commit run ruff --all-files
```

### Dependency Management

```bash
# Add a new dependency
uv pip install package-name

# Update lock file after changing pyproject.toml
uv pip compile pyproject.toml -o uv.lock

# List installed packages
uv pip list
```

## Code Style Guidelines

### Python Style

- **Line length**: 88 characters (Black-compatible)
- **Quotes**: Use double quotes for strings
- **Indentation**: 4 spaces
- **Type hints**: Encouraged but not strictly enforced
- **Imports**: Sorted automatically by ruff (isort rules)

### Logging Conventions

The project uses `loguru` for all logging. The `utils/logger.py` module provides:

- **Console logging**: Configured by default at INFO level with colorized output
- **File logging**: Available via `setup_file_logging()` with rotation and retention

**Usage Pattern**:

```python
from utils import logger, setup_file_logging

# Basic logging
logger.info("Message")
logger.debug("Debug message")  # Won't show in console (INFO level)

# Add file logging
setup_file_logging(log_file="logs/app.log", rotation="10 MB", retention="30 days")

# Structured logging
logger.info("Event", user_id=123, action="login")

# Context binding
contextualized = logger.bind(request_id="abc123")
contextualized.info("Processing")

# Exception handling with decorator
@logger.catch
def risky_function():
    pass
```

### Module Organization

- Place utility modules in `utils/`
- Export public APIs via `__init__.py`
- Tests go in `test/` directory (not a package, no `__init__.py`)

## Security Considerations

1. **Environment Variables**: Use `.env` files for secrets (already in `.gitignore`)
2. **Log Files**: The `logs/` directory is gitignored but created at runtime
3. **Virtual Environment**: `.venv/` is gitignored - never commit virtual environments

## Common Tasks

### Adding a New Module

1. Create directory (e.g., `config/`)
2. Add `__init__.py`
3. Add your modules
4. Update `packages` in `[tool.hatch.build.targets.wheel]` if needed
5. Import from utils: `from utils import logger`

### Updating Project Metadata

Edit `pyproject.toml`:

- `[project]` section: name, version, description
- `[project.dependencies]`: runtime dependencies
- Add `[project.optional-dependencies]` for dev dependencies if needed
